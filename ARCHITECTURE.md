# Архитектура security_camera

Документ снят с реального кода (`main.py`, `notifier.py`, `audio.py`). Фиксирует
потоковую модель, память и известные проблемы/ограничения.

## Потоки

| Поток | Роль | Обмен |
|-------|------|-------|
| `CaptureThread` | читает камеру на полной скорости | последний кадр под `lock`, `frame_seq`, `new_frame` Event |
| `RecognitionWorker` | InsightFace: детект+эмбеддинг+сравнение | один слот `_pending` (последний кадр), результат под `_result_lock` |
| `PersonTracker` | YOLOv8n + ByteTrack | один слот `_pending`, `_tracks` под `_result_lock` |
| `WriterThread` | пишет кадры в mp4 | `queue.Queue(maxsize=queue_size)`, `_lock` вокруг writer |
| `DiskCleaner` | чистит старые записи | файловая система |
| `AudioRecorder` | пишет микрофон в катящиеся WAV-сегменты | `_segments` под `_lock` |
| `TelegramNotifier._thread` | отправка фото/видео + ffmpeg-мукс | `queue.Queue` заданий |
| main-цикл | motion gate, стейт-машина записи | — |

Связь потоков — через «последний кадр» и очереди, без общих мутабельных структур
кроме защищённых `lock`. Это предотвращает гонки, но означает, что при перегрузке
промежуточные кадры теряются осознанно (дропаются), а не копятся.

## Память — узкие места и что сделано

1. **Pre-buffer** (`RingBuffer`). Раньше `list` + `pop(0)` — O(n) на кадр и без
   гарантии по памяти. Теперь `deque(maxlen=pre_seconds*fps)` — O(1) и жёсткий
   предел. При 1080p 5с@30fps это ~150 кадров ≈ 0.9 ГБ — основной потребитель;
   если мало RAM, уменьшайте `recording.pre_seconds` или `motion.process_fps`.
2. **Копии кадров на каждом шаге**: `get_frame()` копирует кадр, `submit()` копирует
   ещё раз в воркер. Один кадр живёт одновременно в 2–3 копиях (main, recognition,
   tracker). Осознанный компромисс ради отсутствия гонок.
3. **`_pending` в воркерах** держит только последний кадр (старые заменяются) —
   очередь не растёт.

## CPU

- Motion gate: MOG2 + `cv2.resize` только на `process_fps`; тяжёлые модели — только
  при движении/трекере/записи. Раньше был «safety check», гонявший InsightFace
  каждые 2 с впустую — убрано.
- `allowed_modules=["detection","recognition"]` и `CPUExecutionProvider` — только
  нужные модули InsightFace, без GPU-провайдеров.

## Известные ограничения (осознанные)

- Аудио и видео синхронизируются по wall-clock; рассинхрон до ~1–2 с допустим.
- Запись (`VideoWriter`, mp4v) пишет **без** звуковой дорожки; звук добавляется
  при отправке (ffmpeg-мукс). `mp4v` → при отправке перекодируется в H.264/AAC.
- `HOME_CAMERA` под системным аккаунтом: аудио-устройство может быть недоступно —
  тогда видео уходит без звука (не критично).
- Recorder/tracker воркеры при некорректном завершении вызывают `os._exit(1)`
  (падение процесса ловится супервизором и Task Scheduler).
