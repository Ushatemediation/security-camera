# Запуск на macOS (и Linux)

## Быстрый старт

```bash
cd security_camera

# 1. Окружение и зависимости (один раз)
./setup.sh                 # или: make setup

# 2. Настройки (один раз)
cp config.example.yaml config.yaml
#   впишите telegram.token и telegram.chat_id

# 3. Регистрация лиц (если ещё не делали)
#    положите фото в known/ и выполните:
make enroll

# 4. Запуск
make run                   # headless
make preview               # с окном превью
```

Если venv уже есть рядом (`../venv` или `./venv`), `run_local.sh` найдёт его сам.

## Разрешения macOS (TCC) — камера и микрофон

macOS не даёт приложению доступ к камере/микрофону без явного разрешения
(TCC — Transparency, Consent & Control). Разрешение выдаётся **тому процессу,
который открывает камеру**, а это ваш терминал или IDE.

### Камера
1. Откройте **Системные настройки → Конфиденциальность и безопасность → Камера**.
2. Включите переключатель у **Terminal.app** (или iTerm2, VS Code, PyCharm — что вы используете).
3. **Полностью перезапустите** терминал/IDE (разрешение применяется при новом старте).

### Микрофон
То же самое: **Конфиденциальность и безопасность → Микрофон** → включить для
вашего терминала/IDE, затем перезапустить его.

### Если пункта нет в списке
Запустите приложение один раз — macOS сам спросит доступ («Terminal хочет
получить доступ к камере»), нажмите **OK**. После отказа система больше не
спрашивает — включайте вручную галочкой из пунктов выше.

### Проверка доступа одной командой
```bash
# камера: должно быть opened: True
python - <<'PY'
import cv2; c = cv2.VideoCapture(0); print("opened:", c.isOpened()); c.release()
PY

# микрофон: должно быть имя устройства
python - <<'PY'
import sounddevice as sd; print(sd.query_devices(kind="input")["name"])
PY
```
Если `opened: False` или «PortAudioError» — вернитесь к настройке TCC и
перезапустите терминал.

> Примечание: при запуске через `pythonw`/фоновую службу macOS проверки TCC
> относятся к тому бинарнику, который запускает процесс. Для локального теста
> это ваш терминал — его и разрешайте.

## Проверка функциональности

### 1. Motion Gate (нагрузка CPU в простое)
Наведите камеру на неподвижную сцену и выполните:
```bash
make cpu          # или: ./scripts/idle_cpu.sh 60
```
Ожидаемо: единицы процентов CPU (в простое тяжёлые модели не запускаются).
В логе `logs/app.log` при движении появятся записи «Лицо: …», при простое — нет.

Сравнить с «голодным» режимом (модели всегда) можно, посмотрев разницу
`Статистика: распознавание=… мс` при наличии и отсутствии движения.

### 2. Запись звука с микрофона
```bash
make run
```
В логе при старте должно быть `AudioRecorder запущен (16000 Гц, буфер 60с)`.
Пройдите перед камерой (движение → запись). После события в `recordings/`
появится mp4, а аудио лежит в `_audio/seg_*.wav`.

### 3. Telegram: сначала фото, потом видео со звуком
1. Впишите `token` и `chat_id` в `config.yaml`.
2. `make run`, создайте движение.
3. В Telegram ожидайте: **снимок (JPEG)** сразу, затем **видео mp4 со звуком**.
   `telegram.send_photo: true`, `telegram.send_video: true`.
4. Если приходит видео без звука — проверьте: `ffmpeg` в PATH, доступ к микрофону (TCC),
   и что событие попало в окно записи.

### Тест без камеры (видеофайл)
```bash
./run_local.sh --source test_clip.mp4
```
Источник зацикливается; удобно проверять пайплайн без доступа к камере.

## Диагностика
- `logs/app.log` — основной лог приложения.
- `service.log` — если запускаете через супервизор (`../HomeCameraService`).
- Камера не открылась → TCC (см. выше) или `--camera 1`.
- Микрофон молчит → TCC → Микрофон, либо `audio.device` в `config.yaml`.
- `ffmpeg: command not found` → `brew install ffmpeg`.
